# i18n — SALIS AUTO

## Runtime

The design uses a lookup table plus a helper: `t(s) = lang === 'ar' ? (AR[s] || s) : s`. Keys are the English string itself, values are Arabic. This is fine at design time but production should use `react-i18next` with proper namespacing.

Port the AR table to a real i18n file:

```
locales/
  en.json   — mirror of AR keys → English (identity)
  ar.json   — port of the AR object in gms-data.js
  de.json   — later
  es.json   — later
  fr.json   — later
  hi.json   — later
  zh.json   — later
```

The original SalisAuto codebase already declares 7 target languages; only EN + AR are populated.

## RTL

- **Never use `left`/`right` in CSS.** Use logical properties: `inset-inline-start`, `inset-inline-end`, `margin-inline-start`, `padding-inline-end`, `border-inline-start-width`, etc.
- **Icons that indicate direction flip.** Chevrons in the design already use `rtl ? "ChevronLeft" : "ChevronRight"`. Keep the pattern.
- **Numbers stay LTR** even in Arabic mode — wrap monetary/date/time spans in `<span dir="ltr">` so 1,234 doesn't get misread as 4,321.
- **Dates**: dual-render `{{ greg }} · {{ hijri }}` when the user opts in.
- **Fonts**: Inter for both languages works, but Arabic renders better with `Noto Sans Arabic` — add it to the font stack.

## Audit

The design uses a detector that:

1. Reads the AR object out of `gms-data.js`.
2. Extracts every `t("…")` call from a screen.
3. Reports any key not in the dictionary.

Port this into a CI check. Fail the build on any untranslated key.

```js
// scripts/i18n-audit.mjs
import fs from 'node:fs';
import { AR } from '../src/locales/ar.js';
const files = fs.readdirSync('src').filter(f => f.endsWith('.tsx'));
const missing = new Set();
for (const f of files) {
  const src = fs.readFileSync('src/'+f, 'utf8');
  for (const m of src.matchAll(/\bt\(["'"'"']([^"'"'"']+)["'"'"']\)/g)) {
    if (!(m[1] in AR)) missing.add(m[1]);
  }
}
if (missing.size) { console.error('Missing AR keys:', [...missing]); process.exit(1); }
```

## Common landmines

- Search placeholders — `placeholder` is an attribute, so its string is captured at first render. If your `t()` reads an async-loaded dictionary, the placeholder can freeze in English. Await the dictionary before mounting, or force a re-render when it loads.
- Toast messages built via string concatenation — `t("Signed in as ") + user.name` — split into two keys or use interpolation.
- Prop defaults in components — `function Btn({ label = "Save" })` — hardcodes English. Use `t` at the call site, not in the default.

## Number formatting

- Use `Intl.NumberFormat("en-US")` for the numeric layer even in Arabic (keeps commas as thousands separator per the design brief). If your customer wants Arabic-Indic digits, switch to `"ar-SA"` — but confirm before flipping.
- Currency: JetBrains Mono font stack; `SAR 12,450.75` prefix even in Arabic (per the SALIS AUTO brand guide).
