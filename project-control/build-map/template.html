Architecture

Every screen talks to a seam, so the backend can land without moving one of them

Screens never call the network. They call a Collection<T> repository. Today that repository reads fixtures; tomorrow the same interface is implemented over HTTP and selected by an environment variable. The database is seeded from the very fixtures the app renders now — so every assertion that passes today must still pass after the swap. A failure means the swap is wrong, not the test.

In plain words: the app is wired to a socket, not to a wire. You can swap what's behind the socket — fake data for a real database — and none of the __CAPS__ screens notice.

Security

The client gate is a courtesy. The wall is on the server.

__ROLES__ roles × __MODULES__ modules × __ACTIONS__ actions is a matrix the app enforces in the browser — which is convenience, not security. Every sensitive operation has to re-validate identity, organization, branch, role, permission, resource ownership and the business rule on the server. Bypassing the UI must still be denied. A cross-tenant read returns 404, never 403 — a 403 confirms the record exists.

In plain words: hiding a button doesn't stop anyone. The check that matters happens after the request leaves the browser, where the user can't touch it.

The short version

What to hold on to

What this build gets right, and the one thing that decides the schedule

  • Nothing is counted by hand. Route tables, tests, gates, matrices and reports all fall out of one generated registry. A hardcoded total is treated as a defect.
  • The unit of completion is a capability, not a file. "Customer management" can be done; Customers.tsx cannot.
  • No agent certifies its own work. An agent may mark its own work DONE; only the release manager sets VERIFIED, and only after re-running the checks.
  • The seam is what makes the backend swap safe. The database seeds from today's fixtures, so every assertion that passes now must still pass after the swap.
  • The client gate is a courtesy. The real boundary is server-side, and a cross-tenant read returns 404 rather than confirming the record exists.
  • Rendering is the floor. __RENDERED__ of __CAPS__ capabilities draw and assert their content; __DATA_BACKED__ are backed by real data, __TABLET__ are tablet-verified and __PROD_READY__ are production-ready. Both facts are true at once, and the second one is the honest one.
  • A journey is the only proof. __GP_PASS__ of __GP_TOTAL__ golden paths pass, __GP_FAIL__ fail and __GP_UNWRITTEN__ have no journey at all. Unwritten is reported as its own state rather than counted green, because not knowing is not the same as passing.
  • W1 decides the calendar. Ten product agents wait on four foundation agents, and the backend does not parallelise. Shortening the foundation is the only lever on elapsed time — everything else is effort, not schedule.
