# SALIS AUTO — Architecture

What exists today, and what the target is. This document describes the actual
implementation; anything not yet built is marked **planned** rather than written
in the present tense.

**Data flow today**

```
Screen → useCollection → repository (fixtures) → generated/tables.ts
```

**Authorization today**

```
RequireAccess → SessionProvider.canScreen → SCREEN_MODULE → PERMS
```

This is convenience only. There is no server, so there is no security boundary —
the client decides what it shows itself. Stated plainly because a reader could
otherwise mistake the RBAC engine's completeness for enforcement.

## Target

**Data flow (planned)**

```
Screen → hooks → repository interface → HTTP client → Fastify
       → authentication → authorization → tenant isolation (RLS)
       → business rules → PostgreSQL
```

The repository interface does not change shape when this lands. `httpRepository`
implements the same `Collection<T>`, selected by `VITE_API_URL`, so no screen
moves. That is the point of the seam.

**Stack (planned)**

| Layer | Choice | Why |
|---|---|---|
| Runtime | Node 20 + Fastify + TypeScript in `server/` | one language across the stack; schema-first |
| Database | PostgreSQL 16 + Row-Level Security | RLS enforces per-row data scope below the application |
| Migrations | Drizzle | typed SQL, plain reviewable migrations |
| Validation | Zod in `packages/contract/`, imported by both sides | one schema is the API type, the server guard and the form validator |
| Auth | JWT access 15 min + rotating refresh 30 d with reuse detection, argon2id | claims carry `{sub, role, org_id, branch_id, scope}` |
| Files | S3-compatible behind `StorageAdapter`; MinIO in dev | swappable, testable |
| Jobs | pg-boss | notifications, reminders, report generation, retries — no extra broker |
| Realtime | SSE | notification and job-status streams |

**Money** is stored as integer halalas and formatted at the boundary. No
financial value is computed in the browser and trusted.

**Multi-tenancy** is `org_id` + `branch_id` on every table, enforced by RLS via
`SET LOCAL app.org_id` per request — not by a `WHERE` clause a developer must
remember to write.

## Generated, not maintained

Three generators, each with a single source of truth:

| Generator | Reads | Writes |
|---|---|---|
| `port-design-data.mjs` | the design bundle | the data layer and icon registry |
| `build-registry.mjs` | routes, screens, specs, RBAC, smoke | the registry, control JSON, the matrix and gap docs |
| `check-no-fake` / `check-tokens` | source + registry | pass/fail against a ratchet baseline |

Nothing in `generated/` is hand-edited. A count written into a document is a
dated snapshot, not a fact — the registry is the fact.

## Deliberate departures from the prototypes

Recorded because each was a decision, not an accident. The full list is in
`app/README.md`; the ones that changed behaviour rather than plumbing:

- **Theme and language persist.** Every prototype read `localStorage` into a prop
  that always resolved to that file's own default, so the stored value was never
  applied.
- **Totals are derived.** `Payments` showed SAR 8,090 outstanding above five
  invoices totalling 9,065. The headline was hardcoded and never reconciled with
  the rows beneath it; it is now computed, so the two agree.
- **Segregation of duties is enforced**, not just documented — a technician
  cannot approve their own QC.
- **Table rows are keyboard-reachable.** The prototypes put the click handler on
  `<tr>`, making every list mouse-only.
- **`InvoiceCreate` actually creates.** Its "Add Line" button was decorative and
  its totals were fixed strings.
