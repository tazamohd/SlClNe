The Repository Seam Pattern

SALIS AUTO decouples UI code from data fetching by introducing a repository interface — a "seam" — between TanStack Query hooks and the actual data source. This allows the same React components and business logic to run against two entirely different backends without modification.

In development, VITE_API_BASE_URL is unset, and the app resolves to a Mock Repository backed by PGlite — a full PostgreSQL engine running in the browser via WebAssembly. This provides offline-first development, instant feedback loops, and deterministic test data without a running server.

In production, VITE_API_BASE_URL points to the Fastify API, and the app resolves to an HTTP Repository that serializes requests as fetch() calls, attaching JWT tokens and tenant context headers.

Zero Config Switching

A single environment variable toggles the entire data layer. No conditional imports, no feature flags in components.

PGlite Advantage

Full SQL compatibility in-browser means dev data fixtures use the same schema and queries as production.

Type Safety End-to-End

Drizzle ORM schemas generate TypeScript types shared by both client and server, catching mismatches at compile time.

Optimistic Updates

TanStack Query manages cache invalidation and optimistic mutations, giving users instant UI feedback while writes propagate.
