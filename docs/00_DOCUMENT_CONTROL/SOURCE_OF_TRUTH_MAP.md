## Facts with no authority in this workspace

Recorded here so nobody looks for a source that does not exist, and so nobody invents one.

| Fact | Status | What would establish it |
|---|---|---|
| Market size, segments, competitor positions | `RESEARCH_REQUIRED` | Primary or cited secondary research |
| Pricing, unit economics, CAC and LTV | `RESEARCH_REQUIRED` | A commercial model with stated assumptions |
| Elicited business requirements | Absent | A business analyst and a stakeholder. The requirements catalogue is reverse-engineered from the implementation and says so on every row. |
| Whether ZATCA output satisfies the regulation | `LEGAL_REVIEW_REQUIRED` | Legal review. The documentation states what the system produces, not whether it complies. |
| Production telemetry, incident history, SLA attainment | Absent | A production deployment. ITIL material describes the intended model, not an operating record. |

## Resolving a conflict

1. Find the fact in the tables above.
2. The authority wins. Always.
3. If the losing document is `GENERATED`, run `npm run docs:generate` — it was stale, and `docs:check` should have caught it.
4. If the losing document is `NORMATIVE`, the discrepancy is a real decision to make: either the code is wrong or the rule changed. Record which in an ADR under `31_ARCHITECTURE_DECISIONS/`.
5. If the losing document is `HISTORICAL`, nothing needs doing. Historical documents are allowed to be out of date; that is what they are for.
